## AV3A is not AVS3 video; alternatives rejected or bounded

- Fixed FFmpeg codec_id.h blob 3859b79d2a39f9b137989bdabd2bda48ca7b424a lists AV_CODEC_ID_AVS3 and AV_CODEC_ID_AV3A separately. LGPL wrapper libarcdav3a.c blob 20afc332f9a3e2d767472b753e8b6a10e2438d94 uses decoder.h, hoa_renderer.h, speaker_renderer.h and actual decoder/HOA/object rendering lifecycle. The upstream AV3A implementation file blob 0b18d0352e5ba35bb357a616fd33cef23b7ec698 carries Huawei 2023 and UWA Code Sharing Policy, not blanket GPL. See native README for policy eligibility/permission gate; inspect notice only, do not execute or materialize that codec in diagnostic builds.
- Exact uavs3d@e72f7c34be2f4de725c1ae498e8c4f3559e99b5b COPYING blob ce30f0fa3022f854345fb04021b1c1fc9882db9c is BSD-3-Clause, recipe uavs3d.sh blob 2050074c4e97728bb0e185b2f8a23d57e9f3316a pins commit, uses 10-bit and ARMv7 NEON, excludes CLI. The fixed FFmpeg libuavs3d.c blob 3eea2051b0267546f88ec1e492ada4e46c494fa7 is the video decoder. Upstream FFmpeg/FFmpeg@17de9f85972c89b5dd81378bea7b80b67b3af7f0 codec_id.h blob 8c78bbce3792e94b243a8fb40642ef705bf852f8 lists AVS3 but not AV3A; allcodecs.c blob edbe44ecc61532d1fda9c7a668a886411de54aa2 declares libuavs3d decoder, not AV3A. This is a candidate for restoring video capability, NOT an AV3A audio substitute.
- [MOLAN-AV3A@1564bd33](https://github.com/baiji6/MOLAN-AV3A/tree/1564bd332205bb46afee8c643776f833020b94b6) NOTICE blob 5561ec9aa0107a6bafcd881d263ed114bbfea9c8 explicitly retains Huawei/UWA policy and identifies mirrored reference decoder e7d244d2; its wrapper uses the same policy, README blob 32ad589884f6fdb7af626f3b926ec0815b4e5c20 describes 12-channel validation (author claim), PCM API and metadata not exposed. No applicable independent grant or exact object/HOA FFmpeg contract established; reject as a nonrestricted substitute.
- [Dreamello/av3a@b44b5321](https://github.com/Dreamello/av3a/tree/b44b5321862385a06ad6c427de5791e18f16c16b) README blob 59025bdb5b662853bfe50e99a49658e39e52408e identifies reference RMv3.3.1 lineage, no independent license grant established. [nilaoda/av3a_decoder@aaf2108a](https://github.com/nilaoda/av3a_decoder/tree/aaf2108a5b4e73fe95687ae88687e554dff829c7) archived README blob 034ef88cacf74b1a499f20224795b8f1a360bab5 itself identifies leaked-source lineage; not adopt, download or execute. Public search does not prove all possible alternatives absent.
- Device vendor Audio Vivid hardware or system codec is not established on both target ABIs/devices and is not the required source-build/FFmpeg object-renderer contract. No proprietary SO or APK substitution.
- A source-build alternative with AV3A disabled can restore independently licensed capabilities, but cannot pass exact feature equivalence. Need lawful source/build/use/distribution permissions for original codec or a genuinely independently licensed decoder plus matching API/codec profile/HOA/object rendering/flush/seek/output and actual samples; no removal of upstream user functionality to make a release.
