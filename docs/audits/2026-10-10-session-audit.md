## 七类输入的验收点

以下只记录输入特征与后续验收要求，不保存用户真实节点、身份标识、密码或密钥。

1. Hysteria2：方括号 IPv6、基础端口、SNI、insecure 与 mport 端口范围分别保留；不能静默忽略端口跳跃。
2. VLESS / REALITY / XHTTP：域名连接地址和 SNI、Host 分离；保留 public key、short ID、spider path、packet-up 与 HTTP path。
3. VLESS / REALITY / gRPC：保留 authority、serviceName 与 mode；不把 serviceName 中的斜杠未经验证地删除。
4. VMess / KCP：解码 JSON 后核对 path 所承载的 KCP seed；无 TLS 时不能因存在 fp 字段而擅自启用 TLS。
5. VLESS / TLS / WebSocket：完整保留路径中的 ?ed=2048；核对项目实际核心所需的 early-data 表达。
6. Trojan / TLS / WebSocket：保持密码原义，并核对与上一项相同的路径和 early-data 行为。
7. VLESS / TLS / WebSocket 域名入口：连接域名与 SNI/Host 不同，不能相互覆盖；保留 /?ed=2560。

输入还包含 Markdown 转义和 mailto 包装。是否要求应用直接容错此类富文本需要与既有行为对比；规范化不能全局删除反斜杠、破坏密码或重复百分号解码。
