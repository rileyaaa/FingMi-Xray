# FingMi-Xray

基于 **FongMi/TV** 进行二次开发。

本项目当前以 **FongMi/TV 5.6.0** 为适配开发版本，在保留原有点播、直播和播放体验的基础上，集成 **XTLS/libXray `libXray.aar`**，为点播和电视直播增加按当前播放会话启用的 Xray 网络通道。

> FongMi/TV 上游仍在持续更新。本文中的 **5.6.0** 仅表示 FingMi-Xray 当前所基于并完成适配的 FongMi 版本，并不代表 FongMi/TV 当前最新版本。

FingMi-Xray 主要用于解决一种比较实际的电视播放场景：

**点播接口可以正常使用、电视直播也能打开，但真正开始播放以后视频卡顿、频繁缓冲，尤其是部分港澳台、海外或跨境媒体线路在国内网络环境下直连体验较差。**

如果家里的路由器没有开启代理，又不方便在 Android TV / 电视盒子上额外安装代理工具，可以直接在播放过程中按需开启 FingMi-Xray 内置的 Xray。

**不创建 Android 系统 VPN、不接管整台电视网络、不长期全局代理。**

需要时开启，只服务当前播放；切集、切台、换源、换地址或退出播放后，当前 Xray 会话结束，并清理相关连接和运行资源。

### libXray.aar

Android 端实际集成的是 **XTLS/libXray** 构建生成的：

```text
libXray.aar
```

本项目当前集成版本为：

```text
libXray AAR：v26.7.28
Xray-core：v26.7.28
```

`libXray` 是 XTLS 提供的 Xray-core 客户端封装层，Android 端通过 `libXray.aar` 集成到应用中。

本项目在此基础上针对 FongMi / Android TV 的播放场景进行了适配。

后续是否升级 libXray，会根据实际兼容性和播放稳定性决定，不会单纯为了追求版本号进行更新。

## 💡 为什么做 FingMi-Xray？

电视播放时经常会遇到这样的情况：

```text
接口可以打开
    ↓
影片信息正常
    ↓
点击播放
    ↓
视频线路直连速度较差
    ↓
频繁缓冲 / 卡顿
```

电视直播也可能出现：

```text
频道可以打开
    ↓
有画面
    ↓
直连线路质量较差
    ↓
不断缓冲 / 卡顿
```

尤其是部分：

- 港澳台直播频道
- 海外媒体线路
- 部分跨境 CDN
- 部分点播视频线路

在国内网络环境下可能出现直连速度不理想的问题。

传统解决方式一般需要：

```text
路由器开启代理

或者

Android TV / 电视盒子额外安装代理软件
```

但很多家庭路由器并没有配置代理环境，而 Android TV / 电视盒子安装和操作额外代理工具也不一定方便。

因此 FingMi-Xray 直接在播放器内部集成了 Xray。

遇到真正需要改善连接的播放内容时，再临时开启。

---

## 🚫 不创建系统 VPN

FingMi-Xray **不会创建 Android 系统 VPN**。

也不会通过 Android `VpnService` 去接管整台设备的网络。

因此它不是：

```text
FingMi-Xray
     ↓
创建系统 VPN
     ↓
整台电视所有 App
全部经过 Xray
```

而是：

```text
当前正在播放的视频
        ↓
用户手动开启 Xray
        ↓
FingMi-Xray 内置 Xray
        ↓
当前媒体播放连接
临时通过 Xray
```

所以开启 Xray 后：

- 不会把整台电视变成全局代理
- 不会代理其他 Android App
- 不会长期改变系统网络
- 不需要建立 Android 系统 VPN
- 不需要另外启动代理客户端

Xray 已经集成在 FingMi-Xray 内部。

---

## 🎯 只作用于当前播放会话

这是 FingMi-Xray 和普通全局代理方案最大的区别之一。

**Xray 只作用于用户当前手动开启的播放会话。**

不会因为开启过一次，就让后面的所有内容长期继续使用代理。

### 点播

例如当前正在观看：

```text
电视剧 第 8 集
```

如果直连播放比较卡，可以在播放菜单中开启 Xray：

```text
第 8 集
   ↓
开启 Xray
   ↓
当前第 8 集使用 Xray
```

当切换到下一集：

```text
第 8 集
   ↓
第 9 集
```

第 8 集对应的 Xray 播放会话会结束。

**第 9 集不会自动继承上一集的 Xray 状态。**

如果第 9 集同样需要使用，再重新手动开启即可。

### 直播

直播同样采用当前会话生效的设计。

例如：

```text
频道 A
   ↓
播放卡顿
   ↓
开启 Xray
   ↓
频道 A 当前播放使用 Xray
```

随后切换：

```text
频道 A
   ↓
频道 B
```

频道 A 对应的 Xray 会话结束。

**频道 B 不会自动继续使用频道 A 的 Xray。**

这样可以避免因为看过一个需要代理的频道，后面的直播频道都一直经过 Xray。

## ⚠️ 点播源兼容性说明

Xray 并不是对所有点播源都一定有效。

目前测试中发现，**部分点播源在开启 Xray 后反而可能出现无法播放的情况**。

这通常和点播源本身的网络策略有关，例如：

- 播放地址限制地区访问
- CDN 只允许特定地区出口
- 视频地址不接受海外 IP
- 接口或播放地址存在地区校验
- 当前点播源本身不支持海外网络线路

因此，Xray 是否适合开启，最终还是要以当前点播源和实际播放线路为准。

可以简单理解为：

```text
当前点播直连卡顿
      ↓
尝试开启 Xray
      ↓
能够正常播放并变流畅
      ↓
继续使用
```

如果开启后反而：

```text
无法播放
加载失败
一直转圈
播放地址失效
```

建议直接关闭 Xray，恢复正常直连。

**不要把 Xray 当成所有点播源都必须开启的功能。**

目前实际使用中，大部分港澳台相关直播或媒体连接表现正常，开启 Xray 后通常可以明显改善直连卡顿问题。

但具体效果仍取决于：

- 当前节点线路
- 节点出口地区
- 点播源或直播源本身的限制
- CDN 策略
- 当前运营商网络质量

所以最推荐的方式仍然是：

> **直连正常就直接播放；直连卡顿再尝试开启 Xray；开启后无法播放则关闭。**

## 🔄 哪些操作会结束当前 Xray？

当前播放内容或播放上下文发生变化时，会结束之前的 Xray 会话。

包括：

- 下一集
- 上一集
- 自动播放下一集
- 切换点播线路
- 更换实际播放地址
- 切换直播频道
- 切换直播源
- 更换播放器
- 播放结束
- 离开播放页面
- 手动关闭 Xray
- 对应的应用后台状态变化

新的播放内容默认重新使用正常直连。

有需要时再手动开启 Xray。

## 🌐 不代理整个 FongMi

Xray 的主要目的，是解决：

**媒体真正开始播放以后，视频线路连接质量较差的问题。**

而不是把整个 FongMi 都放进代理环境。

正常情况下：

```text
首页
搜索
分类
影视详情
点播接口
直播接口
普通 API 请求
```

仍然按照 FongMi 原本的网络方式访问。

可以简单理解成：

```text
点播接口
   ↓
获取影片和播放地址
   ↓
开始播放
   ↓
直连正常？
   │
   ├── 是 → 直接播放
   │
   └── 否
        ↓
   手动开启 Xray
        ↓
   当前视频通过 Xray 播放
```

这样可以尽量减少 Xray 对原版 FongMi 网络逻辑的影响。

## ⚙️ 添加 Xray 节点

进入：

```text
设置
  ↓
Xray 设置
  ↓
添加 / 修改分享链接
```

粘贴节点分享链接后保存即可。

目前节点分享链接主要按照 **v2rayN 导出的标准单节点分享链接**进行兼容和测试。

推荐方式：

```text
v2rayN
   ↓
选择节点
   ↓
复制 / 导出分享链接
   ↓
FingMi-Xray
   ↓
设置
   ↓
添加节点
```

这里需要特别说明：

**v2rayN 只是作为分享链接的导出来源。**

FingMi-Xray：

- 不依赖 v2rayN
- 没有集成 v2rayN
- 没有使用 v2rayN 的代码
- 不需要安装 v2rayN 才能运行

只是目前主要以 **v2rayN 导出的标准分享格式**作为兼容和测试目标。

目前主要处理常见 Xray 分享链接，例如：

```text

Trojan

```

由于不同客户端生成的分享链接格式可能存在差异，因此无法保证所有第三方客户端生成的非标准分享链接都能够正常识别。

如果遇到无法导入的情况，建议优先使用 **v2rayN 导出的标准单节点分享链接**进行测试。

## 🧪 测试节点

添加节点后，可以直接在：

```text
设置
  ↓
Xray 设置
  ↓
测试连接
```

测试当前节点。

测试主要用于确认：

- 节点配置能否正常解析
- Xray 能否正常启动
- 当前节点是否可以建立连接
- 当前网络环境下节点是否基本可用

测试完成后会显示本次连接测试结果或延迟。

建议第一次添加节点以后先进行一次测试，再进入点播或直播使用。

## 📱 手机导入节点

电视遥控器输入一整条分享链接比较麻烦，因此针对 Android TV 使用场景提供手机导入方式。

电视与手机处于同一个局域网时，可以通过手机向电视发送分享链接。

大致流程：

```text
电视打开 Xray 设置
       ↓
进入手机导入
       ↓
手机访问电视提供的局域网页面
       ↓
粘贴完整分享链接
       ↓
发送到电视
       ↓
确认并保存
```

这样可以避免使用遥控器输入较长的：

```text
vless://
vmess://
trojan://
...
```

分享链接。

## 🎬 点播如何开启 Xray？

正常打开影片并开始播放。

然后呼出播放控制菜单。

也就是平时可以调整：

```text
倍速
字幕
音轨
画面比例
播放设置
```

的那个播放菜单。

在这里可以找到 **Xray**。

使用流程：

```text
开始播放
   ↓
发现当前视频卡顿
   ↓
呼出播放菜单
   ↓
找到 Xray
   ↓
开启
```

开启后只影响**当前正在播放的视频会话**。

如果当前点播出现：

- 加载速度慢
- 频繁缓冲
- 播放一会就卡
- 某条线路直连速度较差
- 某些媒体地址直连不稳定

可以尝试开启 Xray。

如果当前直连已经正常，则没有必要开启。

如果开启 Xray 后反而无法播放，说明当前点播源或播放线路可能不适合海外出口，请关闭 Xray 后继续直连。

## 📺 电视直播如何开启 Xray？

进入电视直播并播放频道后，呼出直播控制菜单。

Xray 位于与：

```text
切换源
```

**同级的直播菜单中。**

大致操作：

```text
播放直播频道
      ↓
发现频道卡顿
      ↓
呼出直播菜单
      ↓
切换源 / Xray / ...
      ↓
选择 Xray
      ↓
开启
```

特别是部分：

- 港澳台频道
- 海外频道
- 跨境直播线路
- 直连质量较差的直播源

出现频繁缓冲时，可以尝试临时开启 Xray。

目前实际使用中，大部分港澳台相关连接均可正常通过 Xray 播放，并能够改善直连卡顿情况。

如果切换到其他频道，原频道的 Xray 会话不会一直跟过去。

## 🧹 Xray 关闭后释放资源

FingMi-Xray 没有把 Xray 设计成一个长期驻留后台的代理服务。

当前播放不再需要 Xray 后，会停止对应的运行状态并清理相关资源。

包括：

- Xray Core 实例
- SOCKS 本地监听
- 当前代理连接
- 网络 Socket
- HTTP 连接
- 后台任务
- 与当前会话相关的运行状态
- libXray / Go Runtime 对应运行资源

Xray Core 使用独立的：

```text
:xray
```

私有进程运行。

当前 Xray 会话结束后，会停止 Core，并进行连接和资源清理。

需要进一步回收 native / Go Runtime 内存时，可通过结束独立 `:xray` 进程进一步完成资源回收。

整体逻辑可以理解为：

```text
视频卡顿
   ↓
开启 Xray
   ↓
当前播放使用
   ↓
切集 / 切台 / 换源 / 退出
   ↓
结束 Xray 会话
   ↓
停止相关连接
   ↓
清理运行资源
   ↓
释放相关内存
```

而不是：

```text
打开 FingMi-Xray
   ↓
Xray 永久运行
   ↓
后台一直占用资源
```

---

## 🧠 关于 Android 内存显示

关闭 Xray 后，Core 和相关网络资源会被停止和清理。

但 Android 系统中的内存数值不一定会在界面上瞬间下降。

Android Runtime、native allocator 或系统本身可能暂时保留已经申请过的内存页面，以便后续快速复用。

因此：

```text
系统显示的进程内存
```

并不一定等于：

```text
Xray Core 仍然正在运行
```

本项目会尽量在不再需要 Xray 时停止对应实例和连接，并通过独立 Xray 进程进行资源收口和回收。

## 💤 优化部分电视长期后台后的网络问题

除了 Xray 功能之外，本项目还针对部分 Android TV / 电视盒子长时间运行后的网络问题进行了调整。

部分电视带有：

- Fast Start
- 快速启动
- 快速待机
- 深度待机恢复
- 长时间保留应用进程

等机制。

可能会出现：

```text
FongMi 正常使用
       ↓
电视待机 / App 长时间后台
       ↓
应用进程没有真正结束
       ↓
系统 Wi-Fi / DNS / Socket 状态已经变化
       ↓
重新打开 App
       ↓
首页或点播接口像“断网”
       ↓
彻底结束 App 后又恢复正常
```

这种情况并不一定是真正没有网络。

很多时候是：

**应用保存的旧网络连接状态已经失效，但进程仍然继续复用之前的连接环境。**

本项目针对这类电视场景对恢复逻辑进行了调整。

电视从长时间后台或待机恢复时，会重新整理相关网络状态，包括旧连接和 DNS / DoH 等运行环境，并等待系统网络恢复后再继续进行新的请求。

主要用于改善：

- 长时间待机以后首页加载失败
- 点播接口突然无法访问
- 旧 Socket 失效
- DNS 状态异常
- 网络已经恢复但 App 仍然请求失败
- 必须强制结束 App 才能恢复

等问题。

这部分逻辑采用通用 Android / Android TV 生命周期方案，并不是针对某一个电视品牌写死处理。

## 🔨 编译

克隆仓库：

```bash
git clone https://github.com/rileyaaa/FingMi-Xray.git
cd FingMi-Xray
```

然后使用 Android Studio 打开项目。

等待 Gradle 同步完成后，根据项目当前构建配置进行编译。

也可以根据本地环境使用：

```bash
./gradlew assembleRelease
```

Release 签名以及部分本地构建配置请以仓库当前 Gradle 配置和编译说明为准。
