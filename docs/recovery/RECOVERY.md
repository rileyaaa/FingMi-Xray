# FingMi-Xray source recovery

## Goal

Recover the maintainable source for the published `v5.6.0-xray.5` APK and refactor the Xray integration so future FongMi upstream updates require only a small adapter layer instead of repeated edits across the app.

## Trusted baselines

- FingMi release: `v5.6.0-xray.5`
- primary armeabi-v7a APK SHA-256: `cacc7a90ce082adf955fc80a444b54f8cc86d5b5c3ac7acb13d1392b59928bda`
- cross-check arm64-v8a APK SHA-256: `b5ac05193c1e19809fc7ffb3048f7d75aaa2124eace9953d669f4a81a477c21d`
- upstream FongMi/TV commit: `1a19fee278fa2234da725d61a53bf59b69fe9127`
- upstream version at that commit: `5.6.0` / versionCode `560`
- libXray tag: `v26.7.28`
- libXray tag commit: `80263da83e96b2972455b0a94b13ee1a10e51391`

## Recovery strategy

1. Treat FongMi/TV 5.6.0 source as the readable canonical baseline.
2. Decompile the published FingMi APK and collect:
   - AndroidManifest changes
   - Xray-related classes
   - resources and menu additions
   - network/player lifecycle hooks
   - native libraries
3. Compare recovered behavior against FongMi 5.6.0 instead of treating JADX output as final source.
4. Re-implement the FingMi changes in readable code.
5. Move Xray ownership into an Android library module.
6. Keep app-side changes limited to adapter/integration points.
7. Once the recovery layer passes static review and the user approves the first
   faithful build, build and functionally verify it before modularizing Xray.

## Important behavior that must survive reconstruction

The README from the shipped build documents these behaviors and they are treated as recovery requirements:

- no Android `VpnService`
- Xray only proxies the current media playback session
- VOD and live playback can enable Xray independently
- episode/channel/source/address/player changes end the previous Xray session
- the next episode/channel does not inherit Xray automatically
- Xray runs in a private `:xray` process
- stopping a session closes the core, local SOCKS listener and related connections
- process isolation is used to reclaim libXray/Go runtime memory when required
- settings can import/edit a node share link
- connection testing is supported
- phone-to-TV LAN import is supported
- VLESS, VMess, Trojan, Shadowsocks and Hysteria2-style share links are expected
- long-background / TV standby network recovery logic must be preserved and separately reviewed

## Reconstruction rule

Files generated by decompilers are evidence only. They must not be copied wholesale into the maintained source tree without review.

Where an APK class is substantially identical to FongMi 5.6.0, keep the upstream source and apply only the recovered FingMi delta.

## Branch policy

Recovery work is recorded directly on `main`, as requested by the project
owner. The faithful recovery source stays under `recovery/legacy-src/` until
its APK behavior and integration points are fully checked. The first faithful
build requires the owner's separate approval; routine recovery commits do not
run GitHub Actions.
