# FingMi-Xray 产品需求与恢复原则

本文件记录子源在前两个会话和 2026-09-25 续接时说明的目标，并将原始 `README.md` 的产品意图浓缩为可追踪的要求。原文以仓库根目录 `README.md` 为准；发布版实际行为和代码位置见 `README_APK_BEHAVIOR_MATRIX.md`，不要把本摘要误当成 APK 的运行证明。

## 为什么恢复及重构

**项目核心有两项，优先级按用户 2026-09-25 再次说明：第一是 Xray，第二是部分电视长期后台/待机后的网络恢复。** 模块化的目的在于让这两项功能独立、易于跟进 FongMi 上游；不能把第二项误当成 Xray 进程逻辑。

1. `v5.6.0-xray.5` 的原始开发源码已丢失；先以最终发布的 APK 和 FongMi/TV 5.6.0 上游为依据，恢复可维护、可读的旧行为，保留过去多轮修复的边界条件。
2. 现有发布版将 Xray 改动揉进 FongMi 主程序，更新上游时容易反复冲突。恢复之后应把 Xray 能力放到独立模块，把上游侧改动压缩成明确的播放器、点播、直播、设置及网络生命周期适配点。
3. 上游 FongMi 原有点播、直播、播放器行为要保留。回归目标是发布版行为，不是重新设计一个功能近似的代理。
4. 原始 README 是作者当时写的产品介绍和需求依据；遇到 README、JADX、恢复代码冲突时，用最终 APK 的可验证逻辑纠正反编译误差。v7 为使用中的主要 ABI，v8 用于交叉核对。

## 产品行为

| 范围 | 用户期望及边界 | 原始 README 章节 |
| --- | --- | --- |
| 定位 | 只在当前媒体线路直连卡顿时手动开启；不能创建系统 VPN，不能全局代理设备或其他 App。首页、搜索、详情、点播/直播接口继续使用原有正常网络。 | `为什么做 FingMi-Xray`、`不创建系统 VPN`、`不代理整个 FongMi` |
| VOD | 播放控制菜单有 Xray；当前集/实际播放地址使用，下一集、上一集、自动下一集、切线路/源/地址/播放器、播放结束及离开播放页面时终止，新的内容默认直连。 | `只作用于当前播放会话`、`哪些操作会结束当前 Xray`、`点播如何开启 Xray` |
| 直播 | 在“切换源”同级菜单手动开启；换频道、换直播源、换播放器后不继承。 | `只作用于当前播放会话`、`电视直播如何开启 Xray` |
| 兼容与回退 | 有些视频源不接受代理出口，开启失败或无法播放时允许关闭并恢复直连；不要假定代理总能改善播放。 | `点播源兼容性说明` |
| 节点 | 设置页添加/修改单条分享链接，测试解析、启动、连接及延迟；主要测试 v2rayN 导出的标准单节点 VLESS、VMess、Trojan、Shadowsocks、Hysteria2/hy2，不依赖 v2rayN 软件。 | `添加 Xray 节点`、`分享链接支持`、`测试节点` |
| 手机导入 | 同一局域网手机访问电视已有网页导入入口，提交并保存长分享链接。 | `手机导入节点` |
| 生命周期 | Xray Core 在独立 `:xray` 进程；会话结束停止 Core/SOCKS，清理网络连接和相关运行状态，必要时结束子进程回收 Go/native 资源。内存显示不即时下降不能单独证明 Core 未停止。 | `Xray 关闭后释放资源`、`关于 Android 内存显示` |
| 非 Xray 功能 | Android TV 长时间后台、Fast Start/待机后整理过期连接、DNS/DoH、网络环境，并等待网络稳定再请求；这是 app 功能，不应因 Xray 模块化而丢失。 | `优化部分电视长期后台后的网络问题` |
| 依赖版本 | 发布版以 FongMi 5.6.0、libXray/Xray-core `v26.7.28` 为基准；后续升级须看兼容和稳定性。 | `项目版本` |

## 用户指定的工作方式

- 阅读此前会话、已有开发记录、APK 证据和完整 README 后再恢复；不要拿实验性 `xray/` 当前模块当忠实发布版。
- 尽可能少耗 GitHub Actions。先对照发布版彻底做静态恢复和检查；依赖齐备后优先本地编译，缺工具链时可以借助 AC/Actions，但要明确它能验证什么。2026-09-25 用户授予两次无需再询问的机会，实际消耗记录在 `WORKLOG.md`。
- 用户澄清 AC 也用于**编译缺失的播放器 AAR**，产出后再拉回项目核验和供 faithful 构建使用；AAR 编译是解决依赖的前置工作，不等同于提前宣告 APK 恢复验证完成。
- 先完整恢复并静态核对发布版行为；完成依赖核验后，整套 APK 编译须依照子源此前要求取得明确允许。忠实基准可编译并完成关键行为回归后，再正式把 Xray 迁入独立模块。编译成功本身不等于行为一致。
- 只维护 `main`；所有需求、修复、调试与剩余风险持续记在项目 Markdown 中，让换会话直接接手。

## 模块化的验收方向

| 目标 | 验收标准 |
| --- | --- |
| 上游更新简单 | 对照固定上游提交列出 app 必需适配点；Xray 核心的节点、Core、Binder、网络客户端、会话管理不散落在上游业务文件中。 |
| 功能边界清晰 | 独立 Xray 模块只管理 Xray 相关能力；VOD/直播和播放器调用稳定适配接口；待机网络恢复留在 app。 |
| 行为不退化 | 逐项满足 `README_APK_BEHAVIOR_MATRIX.md` 的 APK 对照项，包括失败/超时/进程死亡、资源清理、媒体旁路网络、节点安全。 |
| 可复现 | 固定上游和 libXray 版本、记录缺失二进制和构建环境，至少有可复查的 faithful 构建及 v7 设备回归结果后再宣称完成。 |
